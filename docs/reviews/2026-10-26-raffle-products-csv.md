# 商品、摸彩與 CSV Code Review

日期：2026-10-26（Asia/Taipei）。分支：`codex/raffle-products-csv`，基底 `origin/main`：`9e165830ac62cc1ac959e855c33105336b9b6fd2`。審查直接讀取工作目錄 diff、新增檔案、相關程式與測試；最終受測版本為本 PR head，不以先前摘要取代檢查。

## 發現與修正

### P2：CSV 在每個品項列重複填入整筆總額

- 位置：`storage.js`，`createSalesLogCsv()`（修正後約 425–455 行）。
- 最小重現：建立三抽，各放一張滴膠貼紙，結帳 600 元後匯出。審查前的三個頂層列各有「該筆總額」600，試算表加總得到 1,800 而非 600。收銀資料本身仍為 600，錯誤在匯出統計。
- 來源：繼承既有 CSV 的重複總額設計，本次新增摸彩使其直接影響抽數／營收分析，非儲存格式回歸。
- 修正：增加唯一訂單合計列，明細不再填入整單總額；銷售數量與實際出庫數量分欄，摸彩頂層及內容不重複計數。保留單價僅供當時品項資訊，不拿獎品零售價當摸彩收入。
- 回歸：`CSV totals and quantities are not multiplied by raffle parent/content rows`。此測試在修正前失敗，修正後通過；瀏覽器另檢查實際下載檔案。

### P2：只匯出有效訂單，無法辨識改單／全額退貨紀錄

- 位置：`storage.js`，`getCsvSaleStatus()`、`appendCsvContents()`、`createSalesLogCsv()`（修正後約 357–455 行）。
- 最小重現：結帳一抽，編輯獎品並確認結帳，再編輯新訂單刪除全部品項完成退貨。審查前因沒有 active 訂單，匯出函式回傳空值，即使歷史紀錄仍在也無 CSV；存在其他有效訂單時，替換／退貨的紀錄同樣消失。
- 來源：既有 active-only 匯出行為未滿足本次「呈現改單與退貨」的稽核要求，並非歷史紀錄被儲存程式刪除。
- 修正：匯出有效、已替換及已退貨紀錄，提供穩定訂單 ID、關聯及狀態。inactive 紀錄的有效營收、銷售與出庫數量均為 0，當時總額留在「原成交總額」，避免當成有效交易或重複出庫。
- 回歸：`CSV retains replacement and refund audit rows with zero effective totals/quantities`。修正前沒有匯出結果而失敗，修正後通過；瀏覽器另從實際改單、退貨操作下載稽核 CSV。

## 其他審查結果

- 六張圖片逐一以 SHA-256 比對上傳原檔，引用及大小寫正確；既有全部商品物件相對 main 僅四項增加圖片，未變更原價格、庫存、優惠或旅行包三色引用。
- 新商品滴膠貼紙 60 元、毛絨徽章開瓶器 100 元，預設庫存沿用 100。新商品的 keys 在舊狀態不存在時，使用預設值，不重設其他資料。
- 摸彩 1～7 抽獨立預期值為 250、500、600、850、1100、1200、1450，移除與重新加入亦驗證；優惠不跨福袋或一般商品，不將獎品零售價加到總額。
- 抽數沒有自由輸入欄，而是每完成一份非空內容新增一個抽次；空內容不能完成，數量自然為非負整數。不新增數量解析或把負數／小數自動修正成交易。
- 庫存負數、非整數、空字串與無效字串的持久化資料會阻擋初始化；可讀取但無庫存的 0／null 不能出獎。庫存不足時整筆結帳不寫入，零售與摸彩獎品合併驗證同一份庫存。
- 獎品是訂單工作副本的快照；編輯、取消或刪除自訂商品不更改原始歷史名稱及金額。改單恢復舊庫存再扣新庫存，退貨回補，不單獨提交中間狀態。
- 結帳、改單、退貨在持續寫入失敗時保留完整記憶體與持久化狀態，恢復後重試只提交一次。沿用單 key 提交與 Web Locks；不新增自動儲存或卸載寫入路徑。
- CSV 使用 UTF-8 BOM，逗號、引號與換行正確引用。Blob URL 在下一次成功建立 URL 時才釋放舊 URL；備援連結可重複下載，錯誤顯示不改變訂單。

- `npm test`：37 項通過，包含既有御守、價格／庫存遷移及儲存安全測試，與本次新增回歸。
